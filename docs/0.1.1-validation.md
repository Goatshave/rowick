# 0.1.1 validation scope

The release owner approved a limited manual validation scope for `0.1.1` on
2026-11-07. This is a separate, explicit exception for `0.1.1` with npm tag
`latest`; the initial `0.1.0` exception remains restricted to its original version.
No exception is granted for `0.1.2`, a prerelease or any later version.

## Required automated verification

All normal type, unit, API, dependency-security, compatibility, package-boundary,
external-consumer, independent XLSX, example and browser gates remain required.
Windows Chromium smoke and remote editing/recovery must pass before publication.
Linux Chromium, Firefox and WebKit and the protected npm publish environment
remain required. No automated gate is skipped or treated as a manual pass.

## Manual coverage

This release changes shared styles and fixes Vue/Svelte selector synchronization.
Actual macOS browser observations are recorded separately in the source-bound
release report. Smaller observed flows do not complete a composite manual check.

The full manual matrix is not complete. Unperformed checks remain `not-tested`
with specific reasons, including:

- Windows desktop NVDA and physical Korean/Japanese IME input.
- Complete Safari/VoiceOver and IME coverage across all optional routes.
- Physical touch and pen hardware.
- Actual 200% browser zoom and 390 CSS px manual inspection on every route.
- Full Excel/Numbers clipboard, workbook-format and summary review.
- Remaining composite filtering, server recovery, layout, analytics and locale
  scenarios without complete manual evidence.

No Windows desktop, screen-reader, device or spreadsheet compatibility claim is
made on the basis of the automated Windows/Linux runs alone.

## Exception controls

The default full manual approval policy is unchanged. The protected workflow must
explicitly select `patch_release_exceptions`; the separate
`patchReleaseException` report entry identifies `fabric0de`, the approval date,
reason, this public policy and its SHA-256 hash. Only the canonical
`Goatshave/rowick` repository and `0.1.1/latest` context are accepted.

Reports must still match the clean committed source and current check contract,
remain fresh and fit the workflow input-size budget. Missing checks, blank
reasons, stale source, simultaneous exception policies and false aggregate passes
are rejected. Record unperformed checks as untested, never as passed. Release
notes link to this scope before publication.
